# Research: clipboard tables

Sources read:
- Microsoft Learn, "HTML Clipboard Format" (updated 2025-04): CF_HTML is registered as "HTML Format", always UTF-8; header Version/StartHTML/EndHTML/StartFragment/EndFragment are byte offsets (zero-padded ten digits is allowed); the fragment sits between the verbatim comments `<!--StartFragment-->` and `<!--EndFragment-->`, and must be one valid element. https://learn.microsoft.com/en-us/windows/win32/dataxchg/html-clipboard-format
- Mozilla bugs 1639972 / 1640726 (2020, still the clearest public evidence): Google Docs and Word Online only keep a table when the pasted fragment holds the whole `<table>` with its `<tr>`/`<td>`, otherwise the rows paste as plain text lines.

Decisions from them: the fragment is always one complete `<table>` with inline cell borders; offsets are computed in UTF-8 bytes with a fixed-width header; a plain-text pipe table goes on the clipboard beside it as fallback. Word (WINWORD) and a browser tab titled "Google Docs" get the HTML; everything else gets the pipe text.
